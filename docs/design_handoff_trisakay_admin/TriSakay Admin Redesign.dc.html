10Audit log — the trail the portal already wrote

Every Flag, Suspend, Reactivate and Deactivate has been writing to account_actions since the roster screens shipped, and every Approve/Reject has been stamping a reviewer — none of it was ever readable in the portal. This screen surfaces both, read-only, to all three PSO tiers, because the point is transparency across ranks rather than an Administrator's private ledger. Two tables, not one merged feed: account actions carry a reason and a linked complaint, review decisions carry a subject and a category, and forcing them into shared columns would mean half the cells reading "—". The filter strip is scoped to the first table, and the read-only rule is stated once, in the header, so nobody hunts for an edit affordance.

11Barangays — cluster reference data, and deleting a row

Ordinance No. 37 s.2018 assigns each barangay to a tricycle cluster, and until now amending that meant running SQL by hand. It is Administrator-only, like PSO Users and System Settings, and it is reference data rather than a queue — so it gets the same inline form the invite screen uses, opening above the table instead of in a modal, with the ordinance cited in the header so the person editing knows what they are editing against. Split barangays are the awkward case the data model allows and the old table hid: the cluster cell reads Split as a warning badge and the notes column carries the boundary rule in words. Delete is the one destructive action here, so it confirms — and the confirm says plainly that ride history keeps its recorded barangay.

12States — validation, feedback, empty, loading

The built portal has one feedback device, an ErrorBanner nailed to the top of the page, so a rejected field sends the reader's eye away from the field they were typing in, and a success has nowhere to appear at all. This sheet replaces it: errors resolve as close to their cause as possible — field-level where a field caused it, form-level only for the whole submission, page-level only for a failed load — and confirmations become one transient toast in the bottom-right, never a banner that shifts the layout. Every string here is the one the code already produces, so nothing needs rewording to adopt this.
