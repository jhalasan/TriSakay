REDESIGN Ride chat: passenger + driver
What's hard in the shipped version
The chat is a generic screen with the other person's name as the only context. It doesn't show the plate, the ETA, or which passenger you're talking to, and a driver with two passengers can mix up their threads. Quick replies look the same as typed text. Every message repeats its time and "Seen". Masked numbers show as a raw "[phone number removed]" plus a long notice. Report is hidden behind a long-press nobody knows about. Errors are red text floating at the top. After the ride ends the composer still shows, but sending fails silently.
What changes
A trip header keeps the ride in view: plate + ETA for passengers, and pickup/drop-off plus a passenger switcher for drivers. Bubbles group by sender, with the time and "Seen" shown only on the last one. Quick replies get their own tinted bubble with a bolt, so they read as status signals. A masked number becomes an inline "number hidden" token. A one-line privacy tip teaches long-press to report, which opens a real sheet. Send errors sit above the composer with Retry. When a ride ends, the composer is replaced by a read-only bar. Same data, same services, and no new tables.
