## Where things actually stand

**All 11 wireframe screens exist and are navigable end-to-end**: Login, Dashboard/Overview, Driver Management, Driver & Tricycle Verification, Passenger Management, Ride Monitoring, Complaints Management, Reports & Analytics, PSO User Management, System Settings, Log out. Typecheck clean, 15 new admin-side tests passing (90/90 repo-wide). Layout is ported from the wireframe exactly (176px sidebar, top bar, wireframe's crossed-box `.ph-box` chart/map placeholders); the palette uses the existing brand tokens from `packages/ui/src/theme/colors.ts` (WCAG-verified navy/green/red) mirrored into `apps/admin/src/styles/tokens.css`, rather than the wireframe's literal grayscale.

**This pass was explicitly frontend-only, by instruction — nothing below is backend-wired:**
- No Supabase client, query, or Auth call exists anywhere in `apps/admin` yet.
- Every screen reads from typed mock fixtures in `apps/admin/src/mocks/*`, routed through a service layer (`apps/admin/src/services/*`) whose function signatures already match the eventual Supabase queries — e.g. `listDrivers()` will become a `.from('users')` join, `suspendDriver()` will become an `account_actions` insert alongside a `users.status` update.
- **F1 is now done (see below)** — `routes/Login.tsx` authenticates for real against Supabase Auth via `useSessionStore`, reads `users.role`, and rejects (signs back out) anything outside `pso_staff`/`pso_supervisor`/`admin`. The dev-only role switcher is gone from the TopBar; RBAC gating is driven by the real signed-in role.
- RBAC gating is fully real and demonstrable at the UI layer (`RoleGate` component, `lib/rbac.ts` mirrors the DB helpers `is_pso()`/`is_supervisor()`/`is_admin()` in `docs/SCHEMA.MD` §7).
- Mock fixtures are schema-shaped (same enum values, column names, and FK relationships as `docs/SCHEMA.MD`) so wiring is a mapper change, not a reshape.

**Database/backend: ready, not a blocker for most items below.** `users`, `driver_profiles`, `tricycles`, `driver_documents`, `passenger_discounts`, `complaints`, `complaint_attachments`, `account_actions`, `fare_config`, `system_settings`, `transactions`, `ratings`, `notifications` all exist with RLS already scoped to `pso_staff`/`pso_supervisor`/`admin` (`docs/SCHEMA.MD` §7). Views `v_overdue_complaints`, `v_expiring_franchises`, `v_flagged_low_ratings`, `v_driver_earnings` already exist and are unread by any app code yet.

## Open decisions / cross-app blockers (flagged, not resolved)

1. **No admin-role service surface exists in `packages/services` yet.** Every function there today is single-user, session-scoped (`getCurrentUserProfile`, `getDriverVerificationStatus`, etc.) — there is no `listDrivers`/`approveVerification`/`triageComplaint`/`listUsers` equivalent shared package function. F3–F13 above will each need a new module under `packages/services/src/admin/` (or similar) rather than querying Supabase directly from `apps/admin` components, to keep query logic out of the UI layer and testable the same way the rest of the repo is (`packages/services/tests`).
2. ~~`match-ride-request` is deployed; `paymongo-webhook` is not~~ — **both are now deployed and verified live** (2026-08-07, see `docs/CHECKLIST.MD` P0). F8/F13 can now expect real `transactions.status='paid'` rows to exist once a passenger actually completes a GCash payment — no longer a blocker for those items.
3. **No email-sending infrastructure exists anywhere in the repo** (no Resend/SendGrid/SMTP integration) — blocks F4's FR-1.6a driver notification and F11's PSO invite flow.
4. **Charting library choice is unmade.** F8 needs one; nothing is installed repo-wide (confirmed via lockfile scan during this pass). Pick when F8 is scoped, not before — the wireframe's `.ph-box` placeholders are intentionally charting-library-agnostic in the meantime.
5. **Feature-toggle persistence (F12) has no target table.** `fare_config`/`system_settings` cover the numeric matching/fare parameters; GCash/Cash/notification on-off switches shown in the wireframe don't map onto any existing schema object — needs a small schema decision before F12 can go fully real.
6. **`react-router-dom@7` was added as a new `apps/admin` dependency** this pass (previously absent repo-wide) — the only new production dependency introduced. `zustand` was also declared explicitly in `apps/admin/package.json` (already hoisted repo-wide via the Driver/Passenger apps, just not previously listed as an admin dependency).
